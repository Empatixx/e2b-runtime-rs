## Konfigurace

Orchestrator se nastavuje proměnnými prostředí se stejnými názvy jako v Go. Ty nejdůležitější:

| Proměnná | Výchozí | Význam |
|---|---|---|
| `GRPC_PORT` | `5008` | Port pro gRPC, health a `/health`. |
| `NODE_ID` | `local` | Jméno nodu v metrikách, událostech a routingu. |
| `ORCHESTRATOR_SERVICES` | `orchestrator` | Role: `orchestrator`, `template-manager` nebo obě. |
| `TEMPLATE_STORAGE_URL`, `BUILD_CACHE_STORAGE_URL` | | Kde se ukládají buildy. |
| `FIRECRACKER_VERSIONS_DIR`, `HOST_KERNELS_DIR` | `/fc-versions`, `/fc-kernels` | Binárky VMM a jádra. |
| `NBD_POOL_SIZE` | `64` | Připravená NBD zařízení. |
| `ORCHESTRATOR_BASE_PATH` | `/orchestrator` | Základ lokálních adresářů: `sandbox/` (`SANDBOX_CACHE_DIR`), `template/` (`TEMPLATE_CACHE_DIR`) a `build/` (`DEFAULT_CACHE_DIR`). |
| `PERSISTENT_VOLUME_MOUNTS` | | Typy volumes a jejich adresáře na hostu, například `nfs:/data/volumes`. Když je nastavená, node sdílí volumes přes NFS. |
| `NFS_PROXY_HANDLE_CACHE_LIMIT` | `16384` | Kolik file handlů si NFS proxy pamatuje pro každý volume. Nad limit je nejdéle nepoužitý handle pro hosta neplatný. |
| `NFS_PROXY_METRICS`, `NFS_PROXY_LOGGING`, `NFS_PROXY_TRACING` | `true`, `false`, `false` | Metriky volání, debug logy a spany NFS proxy. `NFS_PROXY_RECORD_STAT_CALLS` a `NFS_PROXY_RECORD_HANDLE_CALLS` přidají volání stat a handlů. |
| `LAUNCH_DARKLY_API_KEY` | | Feature flagy; bez něj výchozí hodnoty z Go. |
| `OTEL_COLLECTOR_GRPC_ENDPOINT` | | Zapne OTLP metriky, trace a logy. |

## Feature flagy

Limity a přepínače pocházejí z **LaunchDarkly** se stejnými názvy flagů, kontexty (sandbox, tým, cluster, služba) a výchozími hodnotami jako v Go. Příklady:

| Flag | Výchozí | Řídí |
|---|---|---|
| `max-sandboxes-per-node` | 200 | Limit admission, znovu načítaný každých 30 s. |
| `max-starting-instances-per-node` | 3 | Souběžné starty, znovu načítané každých 30 s. |
| `resume-prefetch-source` | `init` | Který prefetch běží při probuzení. |
| `use-memfd` | zapnuto | Paměť hosta v memfd. |
| `envd-timeout-milliseconds` | `ENVD_TIMEOUT` nebo 10 s | Jak dlouho probuzení čeká na envd. |
| `build-cache-max-usage-percentage` | 85 | Kdy se mažou lokální rozdíly. |
| `peer-to-peer-chunk-transfer` | vypnuto | Node čte build, který jiný node ještě nahrává, přímo z toho nodu. Potřebuje Redis a `NODE_IP` jiné než `localhost`. |
| `peer-to-peer-async-checkpoint` | vypnuto | Checkpoint skončí, jakmile je snapshot v cache; upload běží na pozadí. |

## Telemetrie

S nastaveným `OTEL_COLLECTOR_GRPC_ENDPOINT` orchestrator exportuje **metriky, trace a logy** přes OTLP, se stejnými názvy metrik, jednotkami, názvy spanů a atributy jako orchestrator v Go, takže existující dashboardy fungují dál.

## Logy sandboxu

Logy, které uživatel u sandboxu vidí, node posílá na `LOGS_COLLECTOR_ADDRESS`, jeden řádek JSON na požadavek, stejně jako Go. Zahrnují kill, pauzu a checkpoint, odmítnuté pauzy a checkpointy, procesy zabité kvůli nedostatku paměti, CPU a paměť nad 80 % a zaseknutý zápis CPU hotplugu. Každých 20 sekund node volá `/health` v envd a sandbox, který začne nebo přestane selhávat, dostane také řádek. `logs-write-config` umí řádky poslat na jinou URL a zkopírovat je na shadow URL.

## resume-build

`resume-build` je stejný vývojářský nástroj jako `cmd/resume-build` v Go, se stejnými flagy. Spustí v procesu jeden node a probudí build z lokálního úložiště nebo z `gs://`. Bez režimu čeká na Ctrl+C a `-shell` otevře terminál přes envd. `-cmd` spustí příkaz, `-pause`, `-cmd-pause` a varianty se signálem zapíšou nový build a `-iterations` z každého režimu udělá benchmark s tabulkou časů. `-optimize` nahraje prefetch mapování nového buildu, `-fph-bench` porovná velikost memfile s hintingem volných stránek a bez něj a `-gdb` podrží hosta na vstupu jádra pro relaci v gdb. Spouští se jako root na Linuxu s KVM.

## Vypínání

Po `SIGTERM` se node ohlásí jako vypínající se, počká 15 s (pokud není `ENVIRONMENT=local`), aby na něj API přestalo plánovat, nechá doběhnout běžící buildy šablon a pak čeká, dokud API neodstraní všechny sandboxy a nedoběhnou všechny uploady. `FORCE_STOP=true` čekání přeskočí.

Při startu uklidí, co po sobě nechal předchozí běh, stejně jako Go: zabije všechny skupiny procesů `firecracker` na hostu, odpojí připojená NBD zařízení a smaže namespaces slotů `ns-*`, cgroupy `sbx-*` pod `/sys/fs/cgroup/e2b` a složky sandboxů v `SANDBOX_CACHE_DIR`. Počítá tedy s tím, že node patří jen jemu. Počty jdou do `orchestrator.startup_reclaim.reclaimed` a `orchestrator.startup_reclaim.failed` a `DISABLE_STARTUP_RECLAIM=true` úklid vypne.
